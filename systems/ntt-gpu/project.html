ntt-gpu¶

Exact GPU kernels for CKKS: NTT first, then base conversion, Hybrid key switching, and OpenFHE integration. The target workload is N=65,536 on RTX 5090, with RTX 4090 as the compatibility control.

Current state: the CPU reference, Python oracle, portable GPU-schedule simulator, and OpenFHE transform gate are implemented. CUDA source is ready; execution on a real GPU remains the next hardware gate. CPU simulation does not validate GPU barriers or launch behavior.

Build & test¶

Requires CMake, a C++20 compiler, and Python 3. CUDA is optional and detected automatically.

cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure

The eight portable checks cover vector generation at N=64/1024/65536, unit tests, the independent Python oracle, the shared device schedule, the column index/twiddle proof, and the N=8 debug example. Small fixtures keep the quadratic oracle and schoolbook multiplication practical.

With nvcc, three more gates compare CUDA with the same oracle and CPU reference. Array ordering, forward/inverse results, round trips, and polynomial multiplication must agree exactly. See run and debug to step through the N=8 example.

Exact OpenFHE compatibility¶

The optional gate pins OpenFHE 1.6.1 at b59e1f291965f14fbee5172cd83a20f5b856204f:

bash scripts/openfhe_setup.sh

It compares N=65536 NativePoly coefficient/evaluation conversions with our reference, including bit-reversed evaluation order. Cases use 50- and 59-bit OpenFHE-selected primes, zero, maximum, ramp, random coefficients, and independent random inverse inputs.

To reuse an installation, configure with -DNTT_ENABLE_OPENFHE_COMPAT=ON and set CMAKE_PREFIX_PATH to its install prefix. OpenFHE is not required for the standalone build.

First session on a rented GPU¶

bash scripts/autodl_setup.sh

The script finds nvcc, updates source, builds, runs the gates, benchmarks N=65536, and writes hardware details and results to VERDICT.txt. Override the checkout, architecture, or benchmark arguments with NTT_REPO_DIR, NTT_CUDA_ARCH, and NTT_BENCH_ARGS.

The default build targets sm_89 and, with CUDA 12.8+, sm_120. For one known GPU, use -DCMAKE_CUDA_ARCHITECTURES=native (CMake 3.24+).

Design¶

Both backends use the same negacyclic transform convention:

psi is a primitive 2N-th root modulo q; psi^N = -1
forward: A_j = sum_i a_i * psi^((2j+1)*i) mod q
input: natural coefficient order; output: bit-reversed evaluation order

The CUDA schedule splits at 256. Pass 1 gathers 256 strided columns; pass 2 loads 256 contiguous rows. At N=65536, each pass handles eight stages in shared memory. One forward uses two launches and four logical array movements. The strided pass is uncoalesced, so logical bytes are not measured DRAM traffic.

Stage bodies in dev_core.hpp are compiled for both CPU simulation and CUDA. The current __uint128_t remainder arithmetic is a correctness baseline. Shoup/Barrett reduction, coalesced layouts, and register staging are planned optimizations, subject to exact checks and profiling.

Use the work-distribution explorer to inspect blocks, threads, pairs, and twiddle exponents.

Docs¶

Start with NTT and butterflies, then CPU to CUDA. The implementation survey and GPU comparison explain the design choices.

python3 -m venv .venv
.venv/bin/python -m pip install -r docs/requirements.txt
.venv/bin/python scripts/build_docs.py --check
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/docs-site

Open http://127.0.0.1:8000/. See writing and publishing for editing, journals, and GitHub Pages export.
