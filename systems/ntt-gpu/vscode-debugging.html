  • The N=8 example prints coefficients, evaluations and a recovered input. No CUDA device is needed.
  • Use a terminal on any supported CPU platform, or follow the supplied macOS VS Code debugger setup.
Read full notes

Run and debug the NTT in VS Code¶

Use the N=8 CPU example to watch coefficients become evaluations and return to the original values. No CUDA hardware is needed. The terminal commands work on supported CPU platforms; the supplied VS Code debugger setup targets macOS.

One-time setup¶

  1. Open the repository folder in VS Code: code .
  2. If VS Code asks, install the recommended extensions: - CMake Tools - C/C++ - LLDB DAP
  3. Wait for CMake Tools to finish configuring build/debug.

The workspace uses Xcode's lldb-dap; check that Xcode command-line tools are installed.

Run the small example¶

From a terminal:

cmake -S . -B build -DNTT_ENABLE_CUDA=OFF
cmake --build build --target ntt_debug_example
./build/ntt_debug_example

Open the command palette with Cmd+Shift+P, choose Tasks: Run Task, then choose Run: NTT debug example.

The expected output is:

natural-order coefficients: 1 2 3 4 5 6 7 8
bit-reversed evaluation values: 5 0 13 8 9 11 5 8
recovered coefficients: 1 2 3 4 5 6 7 8
roundtrip passed

Debug it step by step¶

  1. Open examples/step_by_step.cpp.
  2. Click left of the transform.forward(values) line to create a breakpoint.
  3. Open Run and Debug with Cmd+Shift+D.
  4. Select Debug: NTT example (step by step).
  5. Press F5. The program first stops at main because stopOnEntry is on.
  6. Press F5 again to reach the breakpoint.
  7. Press F11 to step into NegacyclicNtt::forward in include/ntt/ntt.hpp.
  8. Use F10 to advance one source line at a time.

Watch values, upper_index, lower_index and twiddle_power first. Add stage_pair_distance, group_start_index and pair_offset when tracing how a pair is chosen.

For N=8, the forward transform has three stages with pair distances 4, 2, and 1. Expand values after each butterfly to see the array change in place.

Other shared commands¶

  • Cmd+Shift+B: configure and build the debug example.
  • Test: All CPU checks: build and run the complete CPU test suite.
  • Debug: CPU unit tests: generate the N=1024 fixture and debug the tests.

The debugger deliberately targets the CPU reference. CUDA kernel debugging will be added on the RTX machine using cuda-gdb or Nsight after the native CUDA build is available.

CodeLLDB crash on current macOS/Xcode¶

Recorded workaround for CodeLLDB 1.11.4

The recorded CodeLLDB 1.11.4 / LLDB 19.1.7 setup crashed with SIGBUS on AppleClang symbols. Xcode lldb-dap stopped correctly at main. If an old lldb configuration appears, run Developer: Reload Window and select the lldb-dap configuration.
