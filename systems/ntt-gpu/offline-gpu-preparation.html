Before renting a GPU¶

Do the builds, host tests and documentation on a CPU machine. Rent a GPU when ready to run native CUDA checks and collect measurements. The main target is RTX 5090 at N=65536; RTX 4090 is the planned control.

A November 14 Ada run passed its selected native tests. The current source includes later changes, especially the resident runtime, that still need native verification. D11/P2 remains open on the roadmap; working days are milestones, not rental days.

1. What is ready¶

Observed on the November 16 source increment, in a driverless Linux workspace:

Check Result
CPU/OpenFHE suite 24 CTests pass with CUDA disabled
CUDA-linked host suite 26 CTests pass; GPU-labelled tests excluded
CUDA compilation Stock nvcc 13.0.88 builds sm_89 and sm_120
Resident prototype Host ownership/failure tests and exact OpenFHE comparisons pass
Native execution of this increment Pending; compilation is not GPU execution

The original offline collector record, bench-results-offline-final/report.json, reported OFFLINE_READY and gpu_execution: NOT_RUN. Its older test counts are preserved in the November 12 journal. Toolchains, binaries and generated reports remain in ignored directories. Use the rental survey for dated provider evidence, then recheck the actual offer and profiling permissions.

2. Reproduce the offline preparation¶

Use Linux x86_64, Python 3.12+, CMake 3.24+ and a compatible C++20 host compiler. The pinned installer downloads NVIDIA's compiler/runtime/header components, verifies each SHA-256, retains component notices and installs under build/. It installs no driver and changes no system packages or shell configuration.

From the repository root, with cmake/ctest on PATH:

bash scripts/openfhe_setup.sh
python3 scripts/install_cuda_toolkit.py
python3 scripts/gpu_session.py --mode offline \
  --cuda-root build/toolchains/cuda-13.0.2 \
  --openfhe-prefix build/openfhe-compat/install

The OpenFHE helper pins commit b59e1f291965f14fbee5172cd83a20f5b856204f, NativeInteger 64 and reduced-noise off, and deliberately builds CPU reference tests with CUDA disabled. Its parallelism defaults to two jobs; set NTT_BUILD_JOBS if the machine supports more. The session runner selects project-local CMake/CTest from .venv/bin when present.

The toolkit lock pins NVIDIA components and SHA-256 values. CUDA 13.0.2 contains compiler version 13.0.88. Matching installs are reused; incomplete installs or checksum mismatches fail.

Compiler and dependency portability notes

On this host, CUDA 12.8.93 conflicts with glibc 2.41's sinpi/cospi declarations. Stock CUDA 13 compiles without vendor-header patches. A rental may use another supported OS/toolkit combination; match its driver, toolkit and host compiler. Offline compilation does not establish driver compatibility.

Reuse OpenFHE binaries only across compatible OS, glibc, architecture and compiler settings. Otherwise build the pinned dependency on a matching image before the session, or rebuild it on the GPU machine.

3. Fixes made before rental¶

The synchronous wrapper now owns partial allocations through RAII: resources are released when their owner is destroyed. It selects the owning device for operations and cleanup, validates dimensions/moduli/roots, and rejects wrong-length or noncanonical input before upload. The first nvcc build also repaired a namespace closure and private-type launcher issue; transform arithmetic and stage order were retained.

Host tests and CUDA-linked invalid-constructor tests pass without allocating device memory. Native pre-call setup-failure checks passed in the older Ada batch. Actual driver OOM, partial-transfer errors, wrong-device restoration and cleanup under a failed context remain separate open tests. A nonthrowing destructor cannot report cleanup errors to its caller.

These fixes do not implement the full backend proposal, cache or transactional OpenFHE adapter. The separate resident prototype has its own scope and limits.

4. Prepared native exactness matrix¶

The CUDA/OpenFHE test source is registered as cuda_openfhe_exact. It compares the CUDA wrapper with the independent CPU reference and actual OpenFHE NativePoly transforms/products at N=65536. Its prepared cases include:

  • deliberately unsorted 55/50/60-bit primes selected by LastPrime and RootOfUnity;
  • the exact D8 Q/P moduli and roots, with Q and QlP bases at L=5,4,3,1;
  • zero, one, q−1, alternating bounds, x¹⁷, xᴺ⁻¹ and deterministic dense residues;
  • forward, inverse from independent evaluation arrays, round trip, pointwise multiplication followed by inverse, and the complete negacyclic product;
  • exact complete-array comparisons and unchanged host inputs.

The --smoke option limits that executable to the three-width context with zero and dense patterns for the four Compute Sanitizer tools. This is a bounded smoke scope, not the complete production sanitizer/parameter matrix. All GPU cases are compiled but unrun in this workspace.

The current collector requires seven GPU-labelled gates: cuda_verify, cuda_matches_ref, cuda_oracle_crosscheck, cuda_openfhe_exact, cuda_setup_fault_injection, cuda_benchmark_matrix_exact and resident_cuda_exact. The last two cover the later benchmark matrix and resident operation-chain prototype. The wrapper constructor and resident factory preflights are separate host tests safe without a driver. The older Ada batch exercised the benchmark matrix and setup probe; it predates the new resident path and cannot validate it.

5. First session on real hardware¶

Choose an RTX 5090 image for the primary target. An RTX 4090 can establish the control run; label it accordingly and leave primary-device evidence open. Use an image with a matching NVIDIA driver, CUDA compiler, Compute Sanitizer, and Nsight tools for later profiling. Native architecture mode needs CMake 3.24+.

Use the intended clean source checkout and the pinned OpenFHE install. First check the image, then run the collector:

nvidia-smi
nvcc --version
compute-sanitizer --version
NTT_CUDA_ROOT=/usr/local/cuda \
NTT_OPENFHE_PREFIX="$PWD/build/openfhe-compat/install" \
  bash scripts/autodl_setup.sh

The helper no longer performs an implicit git pull or package installation. It records the selected commit, hardware/driver/clocks/power data and toolchain, requires a native CUDA build plus all OpenFHE/GPU tests, probes the actual device, runs the exact suite and four sanitizer tools on legacy, matrix and resident smoke scopes, then collects the 30/50/55/60-bit N=4096–65536, K=1/3/8/16/24/32/40 GPU-only batch in two timing scopes (140 workloads, 280 jobs). The helper now defaults to --benchmark-scope gpu; request --benchmark-scope all for the previous three-scope, 420-job combined collection. GPU mode rejects dirty source unless explicitly marked exploratory with --allow-dirty.

For full control, call the Python collector directly:

python3 scripts/gpu_session.py --mode gpu \
  --cuda-root /usr/local/cuda \
  --openfhe-prefix "$PWD/build/openfhe-compat/install" \
  --architectures native --benchmark --benchmark-scope gpu

Collect the matching OpenFHE baseline on a local CPU machine, without CUDA:

python3 scripts/gpu_session.py --mode cpu \
  --openfhe-prefix "$PWD/build/openfhe-compat/install" \
  --benchmark --output-dir bench-results-local-cpu

CPU mode records CPU identity, configures CUDA off, runs host/OpenFHE gates and collects 140 CPU jobs. It reports GPU execution as NOT_RUN. Keep CPU and GPU records separate, with matching workload parameters and repetition counts. Both modes support resume within the same clean source/machine/scope context; changing the selection requires a new output directory.

--skip-sanitizers is available for an explicitly limited diagnostic run; its report says EXPLICITLY_SKIPPED. Such a run cannot satisfy sanitizer gates. Missing tools, missing GPU/OpenFHE tests, build/test/sanitizer/benchmark failures all produce a nonzero exit and a failed report. Existing directories are rejected unless explicitly using --resume --output-dir <previous-record>; resume archives the prior report, reruns gates and preserves logs. Open report.json and the named stage logs after every run.

The legacy bench command still uses 46-bit primes and public-call wall time. The collector now separates bench-jsonl public calls, events-jsonl resident work/pinned copies and ntt_openfhe_bench CPU arithmetic. The current CUDA paths compile offline; the new resident path still needs native execution. The CPU comparator is locally verified. Optional --profile needs working nsys and ncu plus counter permissions; it prepares a bounded capture, not a completed D14 bottleneck report. See the protocol and limits.

6. When to stop the rental¶

Use the first GPU session to establish D11 hardware facts, execute D12 smoke and B02 failure-path work, run D13 exactness, and collect the D14 measurements that are ready. Export all raw records before stopping the machine. Analyze and publish results offline for D15.

The collector returning GPU_CHECKS_PASSED still leaves native failure injection, full production coverage, acceptance of raw event timings and Nsight analysis as explicit remaining gates. Completing this offline checklist does not automatically close D11, B02, B03, D14 or P2. The backlog controls those acceptance criteria.
