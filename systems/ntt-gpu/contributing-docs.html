Write and publish the notebook¶

Edit Markdown or the three interactive HTML lessons in this repository. Build and check the notebook, then export it to the personal website. The exported HTML is generated output; edit its source here.

Preview locally¶

python3 -m venv .venv
.venv/bin/python -m pip install -r docs/requirements.txt
.venv/bin/python scripts/build_docs.py --check
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/docs-site

Open http://127.0.0.1:8000/. Rebuild after each edit. The interactive source HTML also works as a standalone page.

Read the site¶

Use the left menu to change pages and search with Ctrl+K / Cmd+K. Each page starts with its main idea. Expand the notes for explanations, commands, evidence or an interactive lesson. A link to a specific section opens any collapsed notes automatically.

Learn explains concepts; Research reports evidence; Plans lists remaining work. The journal records what happened on each calendar date. Its dates are separate from the roadmap's working-day milestones.

Add a daily entry¶

python3 scripts/new_journal.py --date 2026-11-17 --title "Describe the outcome"

The helper creates a draft and never overwrites an existing entry. Append new work to the existing day. Keep the metadata fields title, date, summary, phase and status, and complete these six sections:

Section What to write
Outcome The result
Reasoning Why the change was needed
Changes What changed, with source links
Verification Checks actually run, their environment and limits
Open questions What is unresolved
Next step The next deliverable

Set status: published when ready. Drafts stay off the website. Label reconstructed history and cite commits. Update the roadmap only when a milestone's acceptance checks pass.

Add or edit an article¶

Register an article in docs/site.json with its source, URL, title, group, summary, one to three takeaways and a next_page route. Keep its route and existing heading anchors stable. Relative source links become HTML routes or revision-pinned GitHub links.

Lead with the page's purpose and main result. Define unfamiliar terms before using abbreviations. Put commands beside their expected outcome; keep long source excerpts and historical evidence in labelled expandable sections:

<details markdown="1">
<summary>Source and verification details</summary>

Reference material goes here.

</details>

Use ## for main headings and ### for subsections. Write inline math as \(...\) and display math as \[...\]; KaTeX is bundled locally. Search includes collapsed text. Keep wide tables scrollable inside the page.

For OpenFHE behavior, link the function name to the actual implementation at the pinned commit, with GitHub line anchors. Verify the cited lines and retain the BSD license for literal excerpts. Distinguish existing upstream code from our proposed GPU interfaces.

Preserve the Sunlit Paper theme: warm paper, orange/green accents, Anton headings and Space Grotesk body text. Its source is docs/site-assets/sunlit-paper.css; layout and lesson contrast rules stay in their existing stylesheets.

Validate before publishing¶

.venv/bin/python -m unittest discover -s tests/docs -v
.venv/bin/python scripts/build_docs.py --check
node --test tests/docs/*.test.cjs

The build checks catalog coverage, metadata, routes, local links and fragments. The Node tests run the actual lesson scripts and require Node.js 22+. Inspect changed pages in a browser at desktop and phone widths, including expanded notes, math, controls, search and long tables.

Documentation checks do not establish CUDA correctness. For implementation checks, use the relevant guide:

Area Instructions and scope
Stage indices and twiddles Work-distribution proofs: CPU execution of shared stage helpers
Modular arithmetic Arithmetic contract: bigint and full-size CPU checks
OpenFHE arrays and formats Representation contract: pinned core-library comparisons
Hybrid key switching Operation graph: intermediate CPU arrays and actual keys
Runtime ownership Resident-chain prototype: host lifetime/failure tests; native CUDA pending
Native CUDA session Preparation guide: actual GPU exactness, sanitizers and measurements

Publish with GitHub Pages¶

From this repository:

.venv/bin/python scripts/export_website.py --website-root /path/to/minnow54426.github.io

Review, commit and push the generated systems/ntt-gpu/ files in the website repository. Its Pages workflow publishes the notebook. The exporter refreshes only its managed files and retains the return link to the personal website.

Ordinary pushes to ntt-gpu create a documentation preview artifact; they do not publish the personal website. For a separate project Pages site, choose Settings → Pages → Source → GitHub Actions, then run the Documentation workflow with deploy_standalone enabled. That optional site lives at minnow54426.github.io/ntt-gpu.
