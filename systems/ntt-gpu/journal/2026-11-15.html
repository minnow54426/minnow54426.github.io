Simplify benchmark modes and the website¶

Replace benchmark booleans with named modes and make the homepage and GPU report easier to scan.

Outcome¶

Reviewed the CPU NTT, shared stage helpers, CUDA wrapper/benchmark, measurement helpers and website builder. Simplified benchmark selection without changing NTT arithmetic, kernel launch schedules, exactness checks or timing scopes. Shortened the main GPU report and reduced homepage clutter. No working-day gate advances and no new GPU timing results are claimed.

Reasoning¶

Two booleans encoded three benchmark protocols and allowed redundant flag combinations. Named modes make the interface clearer; one protocol table keeps command names, timing labels and operation counts together. Existing CLI commands and raw JSONL remain compatible.

The homepage repeated long URL strings and a roadmap sequence already available elsewhere. Its GPU status also incorrectly implied that no native validation had run. Readers need the current result and next action first; hardware limitations and evidence must remain available without dominating the page.

Changes¶

  • Benchmark modes: one shared protocol table and a named mode instead of two independent booleans.
  • CUDA interface and command handling: select the mode once; the benchmark implementation reads its metadata/counts from the table.
  • CMake applies the same host-target options in one list.
  • Website builder: preserve every page link, group the directory into native disclosures, remove duplicate URL text and the redundant implementation sequence, and correct the GPU status.
  • GPU report: one key-results table, three findings and the next steps; secondary measurement notes are collapsed. Raw evidence and the November 14 journal remain intact.

Verification¶

On the M1 Pro, all 18 standalone and 22 OpenFHE CPU CTests pass, including the measurement/JSONL and exact OpenFHE checks. The CUDA command translation unit passes host syntax checking with warnings treated as errors. New host tests cover all three command/mode mappings, timing labels, operation counts, unknown commands and invalid mode values.

All 24 documentation tests and 14 interactive Node tests pass; the 35-page build validates every page/journal route and fragment. Browser checks at 1440×960 and 390×844 verify disclosure expansion, phone navigation, the report and a scroll-contained results table, with no page-level horizontal overflow. The report shrinks from 257 to 106 source lines. This is host/UI verification, not a native GPU rerun; primary RTX 5090 validation remains open. CUDA compiler verification is delegated to the existing driverless CI workflow, not a rental.

Open questions¶

The normal resumable collector still needs explicit GPU-only/local-CPU scope selection. Resident pipelines and arithmetic/layout experiments remain the next substantive performance work. Simplification does not establish a new performance improvement.

Next step¶

Publish the checked pages and keep preparing a bounded next GPU batch locally. Do not rent a GPU for documentation or host-only refactoring.
