Exactness before GPU speed¶

Established the OpenFHE transform gate and recorded the GPU NTT research backlog.

Reconstructed on 2026-11-08 from the linked commits and reports. This records documented outcomes, not a contemporaneous account of experiments.

Outcome¶

Added exact transform compatibility against pinned OpenFHE 1.6.1, a GPU NTT survey, and a systematic benchmark plan.

Reasoning¶

CKKS decryption within a tolerance would not establish array-level equality. The gate compares transform values and ordering element by element. The survey identifies modular division, strided access, and host transfers as optimization candidates, not measured speedups.

Changes¶

  • OpenFHE gate.
  • Survey and tuning plan.
  • Compatibility test.
  • Benchmark methodology.

Verification¶

The gate covers N=4096 through 65536, 50- and 59-bit moduli, and deterministic input patterns. The CPU schedule simulator is a separate correctness check. Real GPU execution remained outstanding.

Open questions¶

How costly are device modular remainder and the column memory transactions? Both require named-device profiling.

Next step¶

Define the implementation sequence and architecture contracts.
