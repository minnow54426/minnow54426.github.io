Shared theme and resident NTT preparation

At a glance

Restored Sunlit Paper, separated CPU/GPU measurements and prepared the resident chain. CPU tests and compilation passed; the new runtime had not run on a GPU.

This is a dated record of work on its calendar date. Its test counts, design and next steps describe that time; use the current roadmap for today’s status.

Before you start: No earlier journal entry is required. For current priorities, read the roadmap linked below.

Dated work record

Outcome¶

Restored the earlier website design from Git history at the user's request. The portfolio uses its Sunlit Paper palette, Anton/Space Grotesk typography, photo-filled lettering and full-width photo grids. The research notebook returns to its earlier green and paper theme with an expanded page directory. Current articles, journals, native GPU results and roadmap state are preserved.

Later the same day, the user asked to apply the portfolio theme to the NTT-GPU pages. The notebook now shares Sunlit Paper backgrounds, burnt-orange and forest-green accents, Anton headings and Space Grotesk body text. The earlier restoration remains recorded above; the original design is also backed up on the website repository's backup/old-website-design branch.

A later change on this date separates measurement collection. Rentals can run GPU-only jobs, local machines can run CPU-only jobs, and an explicit combined mode preserves the earlier workflow. No GPU was rented and D11/P2 remains open.

The next change adds a limited prototype for keeping a chain on the GPU: upload two inputs, transform, multiply, inverse-transform and download. A CPU driver that delays operations passes exact comparisons with OpenFHE. The CUDA adapter and corresponding GPU test compile for sm_89 and sm_120. No native execution or speedup is claimed, and D11/P2 remains open.

Reasoning¶

The November 11 shared blue/white redesign changed the visual identity beyond what the user wanted. Restore the presentation from the preceding revisions without reverting the repository or losing later engineering work. Keep the English text, readable lesson panels, keyboard navigation and current controls.

The follow-up explicitly requests a common theme. Keep the portfolio's visual identity while tuning type sizes, code surfaces, tables and controls for long technical articles. Load the theme from source so exports retain it.

The next rental should spend time on native checks and GPU measurements, not repeat the local CPU timing sweep. Each mode records its workload and stable machine identity, so resuming cannot accidentally reuse a measurement from a different selection or host. CPU reference preparation and exact-result checks remain part of GPU validation.

Keep this prototype separate from the complete backend proposal. It leaves inputs unchanged, creates new output buffers and uses one ordered GPU queue. These choices make buffer lifetimes and dependencies easier to test locally. If submission fails and work may still be running, retain its resources. Production recovery, cache limits and the OpenFHE adapter remain later work. Preserve the website's shared theme when publishing the new article.

Resident-chain increment:

  • Added resident.hpp, an internal transport interface and the host runtime: private handle provenance, owned upload/download staging, whole-tower views, implicit/explicit dependencies, per-session budgets and a bounded journal.

  • Published the implementation and limits, linked real OpenFHE source, and updated the backlog and next native task. No roadmap phase or hardware gate is closed by this preparation.

None for the visual work. Future content publishing should retain the established design unless the user explicitly requests a redesign. For the collector, native M1 and new GPU-only session execution remain unverified; primary RTX 5090, native failure handling and full profiling gates stay open.
