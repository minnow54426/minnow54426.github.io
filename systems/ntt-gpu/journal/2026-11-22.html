Survey CUDA kernel optimization

Connected CUDA profiler signals with the project's NTT kernels and prioritized experiments for the RTX 5090 baseline.

At a glance

Connected CUDA profiler signals with the project's NTT kernels and prioritized experiments for the RTX 5090 baseline.

This is a dated record of work on its calendar date. Its test counts, design and next steps describe that time; use the current roadmap for today’s status.

Before you start: No earlier journal entry is required. For current priorities, read the roadmap linked below.

Dated work record

Outcome¶

The survey links timing scopes, profiler signals and optimization techniques to the existing split NTT. The first candidate experiments are Shoup twiddle multiplication and coalesced loading in the strided pass. Their relative impact remains unverified on RTX 5090.

Reasoning¶

The existing Ada comparison showed a median 1.52× device-event forward speedup for group twiddles and 1.01× for the public forward call. The different scopes motivate capturing independent timing and profiling records. The strided pass address calculation suggests a sector-efficiency opportunity. Actual traffic depends on cache reuse and needs counters.

Changes¶

Added and registered the research article. It covers integer arithmetic, memory access, launch geometry, inverse normalization fusion, and the conditions for testing batching or CUDA Graphs.

Verification¶

Reviewed the CUDA kernel, shared butterfly, modular arithmetic and recorded Ada results against NVIDIA's documentation and published NTT studies. The current macOS arm64 environment provided neither nvcc nor nvidia-smi. This work collected no native GPU measurements.

All 27 Python documentation tests and 14 JavaScript lesson tests passed. The site builder validated links and generated 51 pages, including 18 journal entries. The browser blocked local-file preview, so desktop and mobile visual review could not be completed.

Open questions¶

RTX 5090 kernel counters and native acceptance remain open. Shoup table traffic and the cost of rearranging column accesses need measurement.

Next step¶

Collect the unmodified RTX 5090 timings, CUDA timeline and per-pass counters with saved inputs. Use those results to order the independent A/B tests.

Collect repeatable engineering procedures¶

Added a procedures folder for CUDA performance optimization, GPU rental preparation and verification, paired measurement analysis, and notebook publication. The procedures link to exercised examples and distinguish the proposed optimization comparisons from the workflows already used. Registered the procedures in the notebook directory.

All 27 documentation tests passed and the generated site passed local link checks. Verified the directory and all five procedure pages in Chrome at 375 and 1440 pixels. The next addition can follow the next exercised workflow.

Consolidate the procedures¶

Moved the analysis checklist into the rental workflow and linked to the existing analyzer command. The index now points to the notebook guide for publication. Removed the two duplicate pages and their catalog entries. All 27 documentation tests and the site link check passed. Verified the updated navigation and section links in Chrome at 375 and 1440 pixels.
