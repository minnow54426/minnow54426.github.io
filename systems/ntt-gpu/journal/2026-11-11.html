Freeze the OpenFHE NTT and DCRT representation contract¶

Completed D7 with full-size OpenFHE representation checks and prepared the accumulated D3–D7 notebook for publication.

Outcome¶

D7's NTT/DCRT boundary is documented against pinned OpenFHE 1.6.1. The tracker advances to D8, the Hybrid operation graph; P1's architecture gate stays open. The website export includes the previously unpublished D3–D6 work and this D7 contract, with the shared section navigation retained.

Reasoning¶

A round trip alone can conceal a matching forward/inverse permutation or scale error. D7 checks every evaluation address against closed-form monomials and independent inverse basis vectors. A real three-tower DCRT object verifies parameter order and packing without assuming a contiguous OpenFHE allocation.

The pinned source distinguishes SetFormat (conditional conversion), SwitchFormat (always conversion), SetValues (data plus label), and OverrideFormat (label only). DCRT OverrideFormat changes only the outer label. RootOfUnity selects the minimum primitive root, but the FTT cache lookup does not compare roots on a cache hit; consistent imported roots are part of this contract.

Changes¶

  • Added the D7 representation contract, including exact formulas, parameter/root requirements, format APIs, ordered tower packing, active-level behavior, and pinned source references.
  • Added openfhe_representation_tests.cpp and the opt-in openfhe_representation_contract CTest gate.
  • At N=65536, checked four monomials and four independent inverse slots at each of three exact-width primes (50/55/60 bits), minimum roots, canonical values, and format API behavior against actual OpenFHE NativePoly operations.
  • Checked a deliberately unsorted 55/50/60-bit tower list, BigInteger coefficients Q-1 and 2^64+17, CRT reconstruction, flat evaluation-array import, pointwise multiplication by x with negative wrap, and tower dropping.
  • Clarified that FirstPrime(50, m) searches above 2^50: the original gate uses a 51-bit prime there. D7 uses LastPrime for exact-width fixtures.
  • Corrected reference-header comments that conflated mathematical and stored evaluation order or described individual ladder twiddles as odd powers. The NTT algorithm is unchanged.
  • Reused stage-coverage storage across stages in the tile test. This removes the observed GCC 14 Release vector-teardown build failure without suppressing warnings or removing coverage.
  • Registered the article, updated build/test instructions, and advanced the roadmap to D8.

Open questions¶

D8 must trace the exact Hybrid decomposition, Q/QP transitions, key MAC, rounding, and ModDown sequence. D9 still needs explicit buffer/stream ownership, RAII constructor-failure cleanup, and the integration seam. Arbitrary custom-root contexts sharing a modulus are outside the D7 test matrix because of the pinned OpenFHE cache behavior.

Next step¶

Trace OpenFHE 1.6.1 Hybrid key switching and freeze the exact operation graph with intermediate-state fixtures. Preserve bit equality rather than replacing it with approximate CKKS decryption agreement.

D8: freeze the pinned Hybrid operation graph¶

Completed the D8 graph against the clean OpenFHE 1.6.1 checkout at b59e1f291965f14fbee5172cd83a20f5b856204f. The tracker advances to D9. P1 remains open for buffer/device/stream/cache ownership and the final architecture decision.

The source trace fixes contiguous digit partitions, the shortened last digit, coefficient/evaluation transitions, complement-only extension, full-key P offsets at reduced levels, B/A accumulation order, exact CKKS ModDown, and the two-/three- component wrappers. It also records extended ciphertext scaling, delayed QP accumulation, and the source ordering of extended rotation/relinearization. Approximate CRT keeps its unreduced integer sum; substituting canonical CRT or moving ModDown into the digit loop changes arrays.

Added openfhe_hybrid_graph, an opt-in PKE-linked CTest using N=65536 throughout. The deterministic context has M=5, alpha=3, K=3 and two full-context digits. The executable pins all eight moduli/roots. Its scaling-size request is 50, but two selected Q primes have 51 bits; arithmetic uses the exact primes. Levels L=5,4,3,1 exercise full/partial last digits and a partial first digit. Four coefficient patterns (zero, q−1, x^17, deterministic dense residues) use repeatable diagnostic key arrays. Two further cases use an actual key generated from two real secret keys; that key is fixed within each comparison, not across separate random key-generation runs.

An independent arbitrary-precision unreduced-CRT sum and scalar arithmetic check the complete digit INTT, complement conversion/NTT, assembled digit, two MAC outputs, P INTT, Q correction conversion/NTT, and final P-inverse scale. The integer oracle uses BigInteger arithmetic but no OpenFHE conversion tables to compute its expected values. Transform expectations use the already-checked repository NTT with the exact imported roots. Public-core composition, source immutability, in-place add/replace behavior, both extended addFirst settings, delayed reduction, and first-element-only reduction are checked separately.
