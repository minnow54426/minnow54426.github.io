Analyze Ada timings and prepare conversion measurements

Revalidated the November 19 records, compared schedule timings and prepared six resident ModUp/ModDown timing cases for the next GPU batch.

At a glance

Revalidated the November 19 records, compared schedule timings and prepared six resident ModUp/ModDown timing cases for the next GPU batch.

This is a dated record of work on its calendar date. Its test counts, design and next steps describe that time; use the current roadmap for today’s status.

Before you start: No earlier journal entry is required. For current priorities, read the roadmap linked below.

Dated work record

Outcome¶

The raw November 19 archive is available on the M1 Pro and its checksum matches. The earlier cloud workspace's missing-input blocker is resolved here. Revalidated the paired measurements and balanced repeats, then wrote the analysis.

Group twiddles improved all eight device-event NTT workloads. Median legacy/group ratios were 1.515 for forward, 1.503 for inverse and 1.493 for fused multiplication. Resident-interface repeats showed substantially smaller differences. P2/D11 remains open.

Reasoning¶

The source of a speedup matters when selecting the next optimization. Host public calls, the resident interface and device events measure different work. Whole-profile stream creation includes setup excluded by the benchmark. These distinctions make conversion parameter setup, allocation and transfer costs useful targets for the next measurements.

Changes¶

  • Added a reusable paired-record analyzer with manifest, hash, native gate, environment, workload, binary and raw-summary validation.
  • Generated 112 matched operation rows and twelve balanced-repeat rows.
  • Prepared six conversion timing operations covering both ModUp input formats, independent ModDown, resident composition, the host boundary and an intermediate host-roundtrip control.
  • Reused pinned OpenFHE fixture helpers for exact answers outside timing. Every warmup and sample checks its output. Transfer counters check the intended boundaries.
  • Added the GPU conversion selection to the collector, with a bounded conversion-benchmark smoke under all four sanitizer tools before timing.
  • Kept one-time NTT session setup outside timing and explicitly recorded per-operation conversion parameter setup inside timing.
  • Updated the roadmap, analysis and next-rental commands.

Verification¶

All 30 local CPU/OpenFHE CTests and 57 tooling tests passed. The host protocol covers six scopes, special-prime metadata and sample admission. The focused legacy protocol and schedule checks also passed.

The analyzer's synthetic checks distinguish known ratios from damaged logs, incomplete matrices, changed hardware, identical executables, missing sanitizer evidence, mismatched summaries and escaped log paths. They verify record handling. The performance findings come from the original native archive.

The largest host-driver cases use N=65,536, 40 Q towers and three P towers with 30- and 60-bit Q primes. Their output is marked as simulation and is rejected by the native collector. This preparation ran locally.

Open questions¶

The new conversion timing executable needs compiler-only CI and native GPU execution. The resident ModUp/ModDown implementation added after November 19 requires its expanded native and sanitizer gates. Hardware counters and primary RTX 5090 acceptance remain open.

Next step¶

Compile both schedules for sm_89/sm_120 without renting. Then include the conversion exactness, sanitizer probes and timings in the next combined RTX 5090 session. The repeated resident-interface differences motivate measuring parameter and allocation costs before selecting a production optimization.

Follow-up compiler and publication checks¶

Commit edd868f passed compiler-only CI in both schedules for sm_89 and sm_120, including the new native conversion benchmark. Both jobs also passed their host checks. Native GPU measurements remain queued for the next rental.

The documentation build validates 45 published notebook pages with seventeen journal entries. Desktop and phone browser checks cover all 64 tracked website pages, with a transient local photo-page connection retried successfully. The new analysis tables use contained horizontal scrolling so labels and numbers stay readable on a phone. The report's final expanded view passed both widths. Existing local research drafts were preserved separately.
