Follow-up: one group twiddle per CUDA butterfly¶

The older DIF butterfly uses two multiplications and remains correct. Its second multiplier comes from that particular schedule; the negacyclic transform can also be computed with a different schedule. The default CUDA path now uses OpenFHE-style group twiddles: forward adds and subtracts after one multiply; inverse multiplies the difference by the reciprocal, then normalizes once after all stages. The column/row split, reduction, final array layout and launch order are unchanged. The CPU reference remains independent. Configure a separate build with -DNTT_CUDA_LEGACY_BUTTERFLY=ON for the old arithmetic. GPU timing records identify the selected schedule.

The work-distribution, butterfly, GPU code, buffer and OpenFHE representation pages distinguish the new default from the legacy derivation. The explorer shows the global group, table index, and root exponent for each direction.

All 24 OpenFHE-enabled host CTests and the separate legacy simulator gate passed. A supplemental 28-case simulator matrix used three towers per cell, N=256/512/4096/8192/16384/32768/65536 and 30/50/55/60-bit primes. Forward and independent inverse arrays matched pinned OpenFHE directly; products matched the CPU reference. Desktop and phone browser checks confirmed the 65536 lesson renders and the inverse selector shows the reciprocal table entry. The new CUDA source was not compiled with nvcc or run on a device in this session. Existing Ada timings are for the legacy schedule; no P2 gate closed.

Next: compile both CUDA builds, run native exactness and sanitizer gates, then compare resident forward/inverse timings on the same RTX 5090 inputs.

Resident benchmark and standalone basis-conversion checks¶

Added host-wall timing for the resident device chain, the normal host boundary, and an explicit roundtrip through host memory after each intermediate. Every warmup and timed sample is checked against an exact reference product. The collector now pairs the three scopes with the public and CUDA-event records and rejects the host driver's simulated timings. GPU-only mode selects the native CTests and their fixtures, leaving standalone CPU checks on the M1 Pro.

Source review found that the resident CUDA adapter stored root powers in ordinary exponent order, while the new default kernels expected them in bit-reversed exponent order. The adapter now uses the same forward and inverse table builder as the public CUDA path. The CUDA build and native exactness for this revision are pending.

Added a standalone CPU comparison against pinned OpenFHE ApproxModUp and ApproxModDown. At N=65,536, all five Q prefixes with three P towers passed zero, boundary, monomial, and dense fixtures. The test checked 39,321,600 residues. It found 303 examples where keeping the approximate CRT sum and first reducing it to a canonical source value lead to different answers. Both ModUp input formats and the unchanged ModDown source were checked. This is an oracle for the next base-conversion phase.

On the M1 Pro, all 26 CTests and 51 tooling tests passed. The focused legacy host check passed, and the deferred host benchmark produced complete, validated simulation records for 40 primes at both 30 and 60 bits. A local archive of those records passed SHA-256 and listing checks. The next step is to run the new two-schedule compiler-only CI matrix, then execute the bundled RTX 5090 checks.
