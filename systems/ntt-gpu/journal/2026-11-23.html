Batch the next GPU session¶

Added gpu_rental_batch.py to prepare one rental session without requiring a GPU connection during development. Plan mode prints the full queue. Offline mode compiles both sm_120 schedules and runs host checks. Native mode requires a clean checkout and an identified RTX 5090, then selects its UUID for CUDA.

The batch reuses the existing collector for native exactness, 48 sanitizer commands and 64 measurement jobs across both schedules. It adds clock and temperature logging, four order-balanced resident repeats, independent NTT and conversion timeline/counter attempts, raw-record revalidation, and a verified evidence archive. Every collector command shares one deadline; required failures stop dependent work, while unavailable profiles remain separate limitations. Partial records survive failure or interruption.

Updated the rental queue, tooling guide and rental procedure with plan, offline and native commands. The runner creates no rental and does not stop provider billing. Archives preserve the batch status; checksums prove file integrity rather than native correctness. Whole-process profiles include setup and verification and cannot identify an operation bottleneck from their totals alone.

The new orchestration and failure-path tests use synthetic subprocesses, not native GPU execution. All 70 tooling tests passed, including ordered-repeat records replayed through the existing analyzer. Both schedules compiled for sm_120 with pinned OpenFHE and passed all 32 host/OpenFHE CTests each. The real offline batch finished with OFFLINE_READY and verified an archive containing 23 evidence files; its external SHA-256 checksum also passed. This development run records a dirty working tree and no GPU execution. Native mode requires a clean source revision.

All 30 documentation tests and 14 JavaScript lesson tests passed. The site build validated 51 pages and their local links. Browser checks passed for all 70 website pages at 1440, 1024, 375 and 320 pixels, including expanded notes, math, contrast, section links and existing controls. Inspected desktop and phone views of the updated queue. D11/P2 remains open pending hardware evidence.

The final export check found that sibling archive files also need Git ignore rules. Added those rules and require ignored archive paths before a native run, so exported evidence does not dirty the measured checkout. A regression check covers a directory whose archive sibling would be untracked.

Defer hardware work and prepare profiling offline¶

At the user's request, leave native correctness, sanitizers, timings and counters in the later GPU batch. Continued offline work on the profiling boundary rather than choosing an optimization without measured costs.

Added separate resident NTT and conversion profiling executables. Their NVTX ranges distinguish host setup, session creation, uploads, warmups, samples, verification and cleanup; each measured sample also names its operation. Ordinary benchmark builds use an empty backend and contain no NVTX symbols. Profiling variants identify their output, and the benchmark validator rejects it. The rental batch fingerprints the profiling binaries separately, traces CUDA plus NVTX, and selects sample ranges for its bounded counter capture.

Vendored unmodified NVIDIA NVTX v3.3.0-c-cpp headers and their Apache/LLVM license at commit 7c1f2d47f153dac7a0703b162f4b2eaa0ac47c83. Compared every header and the license with the pinned upstream checkout. This avoids a network dependency or a driver requirement for the CPU profiling checks.

All 33 CPU/OpenFHE CTests passed, including actual execution of both NVTX host-driver variants. The scope test checks nesting, idempotent close and exception cleanup. All 71 tooling tests passed. Both CUDA schedules compiled the ordinary and profiling binaries for sm_89 and sm_120 with stock nvcc, without a GPU driver. Confirmed that the ordinary CPU benchmark has no NVTX symbols and the separate profiling binary includes them.

Updated the roadmap's current task and the offline/rental guides to retain hardware work in the deferred batch. Updated B04's evidence scope without closing its bottleneck gate. Native visibility of the ranges, selected counter captures and a measured bottleneck remain unverified. No GPU work was executed, no rental was created, and D11/P2 remains open.

All 30 documentation tests and 14 lesson tests passed. The site build checked 51 pages and their local links. Reviewed all 70 website pages at 1440, 1024, 375 and 320 pixels: 280 page/width checks and 196 expanded source-page checks passed without script, HTTP, contrast or overflow failures. The existing interactive lessons, search, section navigation and portfolio controls passed.

The correctness workflow also watches the vendored NVTX directory so a future header-only dependency update triggers CPU checks and both CUDA builds.
