Standardize the polynomial workload at 65536¶

Remove the 4096 workload from the interactive lessons, defaults, and implementation gates.

Outcome¶

The project workload is now N=65536. The work-distribution lesson has one fixed size, with 256 rows and columns, 16 stages, 524,288 butterflies, and 512 KiB per limb. Both passes launch 256 blocks per limb and use 2 KiB of shared memory per block. Requested value-array traffic is 2 MiB per forward.

Reasoning¶

The user requested removal of the 4096 polynomial and consistent 65536 examples across HTML and implementations. Small teaching examples and the N=64/1024 correctness fixtures remain: the latter exercise boundary schedules and keep the independent quadratic Python oracle and schoolbook product practical. The general transform APIs still accept power-of-two lengths. Historical notebook observations and cited research ranges remain historical.

Changes¶

  • Renamed the work-distribution lesson, updated links and navigation, removed the size selector and comparison column, and corrected the memory, launch, and column-proof counts.
  • Aligned the butterfly and GPU explainers, site shell, current project scope, benchmark plan, and integration plan to N=65536.
  • Removed the 4096 CTest fixture. CUDA comparisons and verification now use the 65536 fixture. The column mapping and optional OpenFHE compatibility gates target 65536. Vector generation defaults to 65536; CMake explicitly requests 1024 for the quadratic oracle.
  • CUDA CLI and AutoDL benchmarks default to exponent 16 only. Explicit benchmark arguments can still explore other lengths.

Verification¶

  • Release C++ build with GCC 14.2 and warnings as errors: all 8 portable CTest checks passed, including the N=65536 schedule and column-mapping checks.
  • Documentation: all 15 Python unit tests passed; build_docs.py --check built 18 pages and validated local links and fragments.
  • Explorer: all 3 Node tests passed, covering all 16 stages, boundary selections, inactive threads, twiddle exponents, and exhaustive per-stage index coverage.
  • Default vector generation produced N=65536, byte-identical to the explicitly sized deterministic fixture. AutoDL shell syntax validation passed.
  • Chromium/Playwright checked all three interactive HTML lessons at 1440px and 375px. No horizontal page overflow or JavaScript errors occurred. The explorer selected 1283/34051 initially, 773/901 at distance 128, and 65534/65535 at the final row/stage. The cost widget initialized at 65,536 and 4,294,967,296 direct products. Desktop/mobile explorer screenshots were visually inspected.
  • No CUDA compiler or OpenFHE installation was present. Those native gates were not run; all implementation execution reported above was on CPU.

Open questions¶

Native CUDA and OpenFHE checks depend on their respective toolkit and library. CPU simulation does not establish GPU launch or synchronization correctness.

Next step¶

Continue the inverse-column correspondence proof at N=65536; no roadmap gate advances solely because the workload scope changed.

Notebook reading review¶

Reviewed all 18 published pages individually. The site now has one section sidebar generated from each page's main headings, including interactive HTML. Desktop sections stay beside the article; smaller screens expose the same links through Sections in the top bar. The current section updates while scrolling, and keyboard users can open, close, and follow section links.
