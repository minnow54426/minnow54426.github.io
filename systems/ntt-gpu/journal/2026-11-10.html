Prove inverse correspondence and complete stage coverage¶

Completed D3–D6: inverse/stage proofs, CUDA dataflow, arithmetic bounds, and independent adversarial checks.

Outcome¶

D3 is complete. The tracker now points to D4: contiguous tile kernels and exact global-stage coverage. No GPU arithmetic or launch behavior changed; two source comments were clarified. The P1 architecture gate remains open. Follow-up: D4 is also complete. The tracker now points to D5 constructor, buffer and public-API dataflow. D3 and D4 are being committed together at the user's request; no push or website publication was requested this turn. D5 follow-up: completed the constructor/buffer/API map and advanced the tracker to D6. The user requested committing and pushing this follow-up; the earlier D3/D4 commit is 404e88a. Website export is a separate action.

Reasoning¶

The inverse uses the same column pairs and exponent indices as the forward transform, but reciprocal powers. Untwiddle the difference leg first, form sum/difference, then apply the inverse ladder to the lower result. This composition returns twice the original pair. Reversing all log2(N) stages returns N times the input, so one final modular N-inverse scale suffices.

The inverse must execute near row stages first, far column stages second, and scaling last. This is three launches at both endpoint sizes, not two. The bit-reversed evaluation output of forward is the inverse's direct input; neither direction needs a separate bit-reversal pass.

D6 follow-up: arithmetic bounds and adversarial tests¶

Outcome and reasoning¶

D6 is complete; the live tracker advances to D7, not past the P1 architecture gate. The arithmetic contract records preconditions, temporary-width proofs, canonical-range induction, the exact test ladder and a concrete deferred adversarial checklist. No reduction algorithm, kernel geometry or public API changed.

The implementation uses canonical residues after every operation, not lazy reduction. A 60-bit modulus still needs a product wider than uint64_t. The arithmetic-header comment incorrectly counted CPU butterfly multiplies: the CPU loop uses three including twiddle advance; shared device helpers use two with table lookup. Corrected the comment and made q>0 explicit.

Changes¶

  • Added a compiled arithmetic probe and full-size tests.
  • Added Python arbitrary-precision comparisons for 14,956 primitive results, including boundary moduli/operands, full-width products, large exponents and valid/zero-input inverse behavior.
  • Added N=65536 two-sided roundtrips and canonical-range checks for six patterns at 50/55/60-bit primes, plus the closed-form negative wrap product x^(N-1) * x = -1. Registered both gates in CMake/CTest.
  • Registered the D6 article in the generated HTML notebook and linked the dataflow article, validation instructions and roadmap to it.

Verification¶

  • All 12 standalone CTests passed, including both new arithmetic gates.
  • Rebuilt the opt-in OpenFHE configuration and ran openfhe_exact_compat: passed against locally installed OpenFHE 1.6.1 at N=65536.
  • Compiled the new C++ test with Clang AddressSanitizer and UndefinedBehaviorSanitizer; both the 14,956-result Python comparison and all full-size patterns/products passed with no sanitizer diagnostics. Invalid preconditions such as q=0 were deliberately not executed.
  • All 23 documentation tests, 4 explorer tests, and the 20-page documentation build/link/fragment checks passed. No shared layout or interaction changed; this update adds article content.
  • This is macOS host execution. No nvcc build, actual GPU run, race check or GPU performance measurement was performed or implied.

Open questions and next step¶

The constructor assumes primality, the public API assumes canonical residues, and parameter-search helpers are unsafe for some invalid dimensions/bit counts. The article records these as input-contract/hardening work, not tests that already pass. Native CUDA checks of the new 50/55/60-bit matrix remain P2/P3 work. D7 next traces OpenFHE coefficient/evaluation order, root selection and DCRT tower representation. Personal website export/publication is separate from this repository commit and was not requested for D6.
