AutoDL rental checklist and beginner visual guides

Recorded the next-rental Nsight access check, reviewed all 52 notebook pages, and added exact beginner explorers with optional Three.js views.

Before you start: No earlier journal entry is required. For current priorities, read the roadmap linked below.

Dated work record

Outcome¶

Recorded an unchecked AutoDL profiling-access TODO for the next rental. No rental was created and no GPU work ran.

Later on the same day, reviewed all 52 notebook pages for beginner teaching opportunities. Added four shared visual explorers, embedded on nine relevant articles, and linked visual prerequisites from the remaining articles. The home page and shared footer make the explorers reachable from the complete notebook. The existing English Sunlit Paper theme and measured evidence remain.

Reasoning¶

An installed profiler and container root access do not prove that the host allows GPU counters. CUDA/NVTX tracing and Nsight Compute metrics must be checked separately on the actual instance. The verification should happen before spending the rental on the long test and measurement batch.

For beginners, the hard questions are concrete: which two numbers form a butterfly, which addresses a thread owns, what a prime tower contains, and which arrays cross the CPU–GPU boundary. Exact labelled diagrams and short calculations answer those questions before the proofs. Optional 3D views help inspect structure; dated results, prices, contracts and journal entries remain readable text and tables rather than synthetic performance scenes.

Changes¶

The rental queue now specifies the required device/tool metadata, a small CUDA/NVTX trace, an actual SM/L2/DRAM counter capture, and retained commands, logs and reports. The rental procedure links to that TODO, and AGENTS.md requires future rental work to follow it. The batch's later operation profiles remain separate from this early manual access check.

The new teaching models cover an eight-value group-twiddle negacyclic NTT, all sixteen forward stages of the 65,536-position thread layout, a four-value RNS polynomial and full-size byte accounting, and resident versus separate-call transfers. Small examples are explicitly distinguished from full-size arrays. The models do not implement Hybrid key switching, approximate basis conversion or native CUDA execution.

The presentation module starts with an interactive SVG diagram and exact text values. A reader can request a local Three.js 0.160.1 view and rotate it using a labelled keyboard-accessible slider. There is no animation loop or runtime CDN request. Controls remain usable without WebGL; context loss returns to the diagram. Without JavaScript, the initial static diagram and explanation remain. Wide diagrams scroll inside their frames so phone labels retain a readable size.

Kept Three.js's MIT license and download provenance beside the pinned library. The page-by-page review records why each page gets an explorer, a prerequisite link, or shared visual navigation. Existing proofs, OpenFHE citations, lesson controls and historical records remain available.

Verification¶

Checked the checklist against the existing rental procedure and batch order. All 30 documentation tests passed. The builder validated 52 notebook pages and their local links. Browser checks passed for all 71 website pages at 1440, 1024, 375 and 320 pixels: 284 page/width checks and 200 expanded source-page checks, with no script, HTTP, math, contrast or overflow errors. Existing lesson and portfolio interactions also passed. This task records a future check; it does not confirm AutoDL support.

For the visual work, all 32 Python documentation tests and 18 JavaScript tests passed. The new tests compare the small NTT with independent direct negacyclic sums and check complete address coverage for every forward stage. They also check RNS values, byte counts and transfer boundaries. The builder validated all 52 pages and local links.

Chromium checks passed across all 71 website pages at 1440, 1024, 375 and 320 pixels, including expanded notes, math, contrast, section links and existing controls. Targeted explorer checks covered all four models at 1440, 375 and 320 pixels: lazy local Three.js loading, software WebGL rendering, camera rotation, keyboard activation and context-loss recovery. Separate checks passed with WebGL unavailable and JavaScript disabled. Browser 3D rendering is a presentation check, not a native CUDA or rented-GPU test.

Open questions¶

Does the next AutoDL instance permit both tracing and the required counters? Record confirmed, blocked or unverified separately for each capability. A permission failure leaves the hardware-profiling acceptance gate open.

Native performance and the new resident conversion path still require the deferred rental batch. Teaching diagrams establish neither performance nor GPU acceptance. Future visual extensions should preserve exact upstream semantics rather than replacing approximate CRT with simple remainder pictures.

Next step¶

At the next rental, run the small access probes first and save their results in the session archive. Check off the verification TODO once both capture attempts and their results are recorded, including a blocked outcome. Continue independent correctness and benchmark work when counters are unavailable. D11/P2 remains open.

For a new reader, start with the butterfly explorer, then inspect thread addresses, prime towers and transfer boundaries.
