Make the 4096-point CUDA schedule tangible¶

Added an interactive explanation of polynomial layout and block/thread ownership.

Outcome¶

Added a standalone HTML learning page explaining the current forward CUDA schedule using a concrete 4096-coefficient polynomial and one RNS limb. No CUDA implementation or roadmap gate changed. Later follow-up: completed the D1 index/memory map for both target extremes and advanced the working-day tracker to D2; the P1 architecture exit gate is still open. Subsequent D2 work completed the column index/twiddle proof and exhaustive stage-helper checks; the tracker now points to D3 inverse-column work.

Reasoning¶

Line-by-line reading obscures the overall work distribution. The explanation starts with data ownership: columns for the four far stages, then rows for the eight near stages. Interactive stage, block, and thread selection shows how butterfly pairs change, including inactive threads in the baseline schedule.

Changes¶

  • 4096-point NTT work distribution.
  • Registered the learning page in the site catalog.
  • Exported the existing interactive explanation with a standalone runtime and added context about synchronization, shared memory, and limb-major storage.
  • Formatting follow-up: replaced the exported iframe/runtime with a small, self-contained lesson. Added consistent notebook typography, numbered sections, jump links, side-by-side pass descriptions, and an integrated light-themed explorer. The page now scrolls as one document; controls and pass descriptions stack at narrow widths. Mathematical content and thread mapping are retained.
  • Added N=65536 to the same explorer, preserving the existing page URL and N=4096 example. Sparse row rendering includes selected operands and labels all omitted rows instead of drawing 256 rows.
  • Documented the 256×256 layout, 8+8 stages, 512 KiB per-limb storage, 2 KiB shared memory per block, active thread ranges, stride-2048-byte column accesses, contiguous row accesses, and logical value-array traffic.
  • Added a three-limb N=65536 fixture to the portable CTest schedule gate and dependency-free Node tests of the actual explorer script.
  • D2: added the CPU-offset identity J = 256j + r, the pair-ownership bijection, both multiplier exponents, bit-operation equivalence, and table bounds to the HTML page, with six first/intermediate/last-stage examples.
  • The explorer now displays CPU offset J, ladder exponent d, and difference exponent E for active threads, and no twiddle read for inactive threads.
  • Added tests/column_mapping_tests.cpp and the column_mapping_check CTest target. Two basis-input probes execute the production helper using tagged power tables; all destinations and exact selected entries are checked independently of the helper's own index formulas.

Verification¶

  • Installed/confirmed docs/requirements.txt in the isolated .venv.
  • .venv/bin/python -m unittest discover -s tests/docs -v: all 15 tests passed.
  • .venv/bin/python scripts/build_docs.py --check: built 17 pages and validated local links and fragments.
  • Browser inspection at desktop and 375px embedded viewport widths: controls render and reflow; selecting distance 128 gives positions 773/901 for block 3, thread 5, and distance 1 gives 778/779.
  • This documentation work does not constitute a real GPU run or benchmark.
  • Formatting follow-up verification: all 15 documentation tests and the 17-page link/fragment build passed again. Browser inspection confirmed the desktop layout and 375px reflow, and the distance-128 control still displays global positions 773/901 for block 3, thread 5.
  • N=65536 follow-up: node --test tests/docs/work_distribution.test.cjs passed 3 tests, including all-stage selected-pair checks and complete index coverage for both sizes. ctest --test-dir build -R '^device_schedule_check$' --output-on-failure passed the schedule gate plus its 4 fixture generators, including N=65536 with three primes. The simulator compares forward arrays, round trips, and multiplication against the CPU reference. These are CPU results, not real CUDA results.
  • Browser checks of the extended page at desktop and a 375px viewport passed: N=65536 selects 16 stage controls and displays 1283/34051 for the first stage at block 3/thread 5. Comparison and explorer tables remain separate; selected operand rows stay visible in the sparse matrix.
  • D2 checks: ctest --test-dir build -R 'column_mapping_check|device_schedule_check' --output-on-failure passed both gates and four fixture generators (6/6). The column gate checks 8,192 + 262,144 pairs, using 540,672 active-pair probes, plus every inactive thread at every column stage. Every global index and active thread owner is covered once per stage. All 3 explorer tests (now including displayed twiddle exponents), all 15 documentation tests, and the documentation build/link checks also passed. These remain CPU-only checks.
  • D2 browser review: proof text and formula blocks reflow at desktop and 375px widths; the live N=65536 example displays J=1283, c=ψ^32768, and w=ψ^2566 for column 3/thread 5 in the first stage.

Open questions¶

The first pass uses few butterfly threads and strided global accesses. Changes to that baseline require correctness checks and measurements on real hardware.

Next step¶

D3: derive how the inverse-column DIT butterfly undoes each forward butterfly, including the final N-inverse normalization and reversed stage order.
