Explain NTT concepts in plain English

Explained NTT formulas, prime-tower data and butterfly merges, then reviewed all 40 notebook pages and rewrote unclear passages for beginners.

Dated work record

Outcome¶

Expanded exact evaluation and inverse formulas for beginners. The section now explains the symbols, distinguishes coefficient indices from stored evaluation positions, and works through a complete forward and inverse example. The transform contract and implementation are unchanged.

Reasoning¶

The compact formulas assumed that readers already knew polynomial evaluation, fixed-width bit reversal and modular inverses. Explain each operation before combining them. A four-point example makes the stored ordering visible without requiring a reader to follow a 65536-element calculation.

Keep the production formulas at N=65536 and label the small example explicitly. Put the cancellation proof in optional notes, so readers can follow the calculation before studying why it works.

Changes¶

  • Added a symbol table for coefficients, memory indices, root indices, roots, bit reversal and N-inverse.
  • Explained why odd powers are roots of x^N+1 and mapped the first five memory positions to their natural point indices and root exponents.
  • Read forward as polynomial substitution and inverse as a weighted sum with modular normalization. Distinguished negative powers from array indices and decimal reciprocals.
  • Added N=4, q=17, psi=2 with coefficients [1,2,3,4], stored evaluations [15,11,13,16], inverse roots [9,8,15,2] and recovered coefficients.
  • Added an optional geometric-sum explanation and retained the existing diagnostic probes, upstream source citations and section anchor.

Verification¶

Direct modular evaluation gives the displayed forward values. A separate calculation solves the evaluation equations using Gaussian elimination with arithmetic modulo 17. It recovers the original coefficients. The inverse weighted sums modulo 17 are [4,8,12,16]; scaling by 4-inverse, 13, returns [1,2,3,4].

A temporary C++20 executable using the actual NegacyclicNtt header independently checks the forward result and inverse of the literal displayed evaluation array. Both pass with compiler warnings treated as errors. All 27 documentation tests and 14 Node interaction/math tests pass before the final publication build. These are arithmetic, CPU and documentation checks, not a new GPU run.

The 40-page build, including 14 journal entries, validates local links and fragments. Chromium passes four focused checks at 1440/1024/375/320px for the symbol guide, original section bookmark, worked arrays, expanded inverse proof, formula rendering, contrast and contained table scrolling. All 59 website pages also pass desktop and phone layout/math checks (118 page/width checks), without script or HTTP errors. Desktop/phone screenshots were inspected; main equations use multiple lines and the worked table has compact, explained symbols. Publication and live checks follow the source commit.

Open questions¶

No transform or roadmap decision changed. The current native RTX 5090 and resident-runtime validation work remains tracked separately in the roadmap and next-session guide.

Follow-up: explain the three-tower data and byte counts¶

Expanded the big picture from a size summary into a data walkthrough. It now distinguishes one RNS polynomial from ciphertext components and decoded slots, shows coefficient reduction and tower-major packing, and derives word indices, byte offsets, 512 KiB per tower and 1.5 MiB per polynomial.

The teaching example uses N=4, q=[17,41,73], roots=[2,3,10] and coefficients [1,−2,20,100]. Reducing each coefficient under each prime and storing one whole tower after another gives [1,15,3,15, 1,39,20,18, 1,71,20,27]. The first tower transforms to [10,16,3,9] without changing its four-word payload. The section labels this as a small example and keeps N=65536 as the project workload.

Added actual NTT multipliers and modular inverse-length values. Explained why each tower’s multiplier table reserves N+1 words, and distinguished the two polynomial buffers from the four arrays of fixed constants. The six-buffer total is 6,291,552 bytes; only 3,145,824 constant bytes are uploaded at construction. Corrected the later table-index explanation to distinguish the default bit-reversed exponent from the legacy exponent.

A temporary C++20 program using the actual CPU NTT and transform_twiddles passes the residue/packing, transform/inverse, twiddle, normalization and payload checks with warnings treated as errors. Independent modular evaluation and CRT reconstruction confirm the example modulo Q=50,881. All 27 documentation tests and 14 Node tests pass. These are CPU/source/documentation checks; no GPU run or roadmap gate is added. The three-tower page passed browser checks at 1440, 1024, 375 and 320 pixels. Its tables have keyboard-focusable horizontal scrolling, preserving whole numbers and labels on narrow screens.

Follow-up: derive the butterfly invariant from the negacyclic merge¶

Expanded the butterfly invariant with the factorization of x^(2d)−β into x^d−α and x^d+α, where α²=β. The child remainders U±αV explain the default group-twiddle butterfly, its per-stage polynomial meaning, its final bit-reversed evaluations and its canonical stored range. Reversing a merge gives 2u and 2v, which explains the single final N-inverse normalization.

Added a four-word example using N=4, q=17 and ψ=2, including both forward and unnormalized inverse stage arrays. A separate disclosure derives the CPU/legacy implicit twist and explains why its intermediate arrays differ. Corrected the adjacent arithmetic-work paragraph: the default helper uses one modular multiply per butterfly, the legacy helper two, and the CPU reference three including twiddle advancement.

Temporary C++20 probes compiled with warnings as errors in both default and legacy configurations confirm the published stage arrays, final CPU agreement, roundtrip, and all 867 canonical pair merges for three example twiddles. Independent Python polynomial evaluation and factor remainders agree. These are CPU checks of shared helpers, not CUDA execution. Documentation tests pass after both article updates. Both revised articles pass browser checks at 1440, 1024, 375 and 320 pixels, including rendered equations, contrast, bookmarks, table scrolling and the CPU-reference disclosure. Screenshot review confirmed readable desktop/phone text and numeric tables. All 59 website pages also pass desktop and phone checks (118 page/width combinations), with no page-wide overflow, math errors, HTTP failures or script errors. The existing Sunlit Paper theme is preserved.
