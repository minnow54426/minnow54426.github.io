Connect resident NTT and basis conversion¶

Outcome¶

The source and website repositories were pulled to 52b87ac and 40e004d. The November 19 journal records the completed Ada run, but its raw archive is not present in this cloud workspace. No connected Mac document session or GitHub release containing the archive was found. Requested the archive from the user's M1 Pro before calculating or publishing performance findings.

Reasoning¶

The recorded 48 measurement jobs and four order-balanced resident repeats need their original samples. A test-pass count cannot establish the relative speed of the schedules. The Nsight timeline includes session setup, so its whole-trace totals cannot be substituted for steady-state timings.

Changes¶

Prepared analyze_batch.py and its control tests under the local directory /workspace/scratch/ntt-gpu-analysis/. The analyzer uses the repository's existing JSONL validator, checks each log against its manifest hash, checks the complete selected workload matrix, and requires matching source, hardware, parameters and measurement settings across schedules.

It emits one CSV row per matched operation and timing scope, with median, fifth/ninety-fifth percentile and legacy/group median ratio. It keeps public, event and resident-interface timings separate. The balanced repeats and setup-aware timeline interpretation remain separate analysis steps once the original files are available. These local helpers are preparation rather than a new production collector interface.

Verification¶

Eight synthetic control tests pass: known statistics and ratios, modified log hash, incomplete sanitizer checks, different hardware, identical binary identities, inconsistent report summaries, a wrong matrix cell, and a path outside the record directory. These tests establish parser behavior only; none is GPU execution or an observed performance result.

Open questions¶

The November 19 .tar.gz archive from the M1 Pro's build/gpu-session-20261119/ directory is required. Its archive checksum, balanced-repeat records and timeline exports must be inspected after receipt. No native milestone or performance conclusion changes during preparation.

Next step¶

Receive and verify the archive, analyze the paired measurements and balanced repeats, inspect the CUDA timeline with setup excluded where appropriate, then publish the supported findings and their limitations to the notebook. The timing report remains blocked on that input. The independent implementation work completed later on this date is recorded below.

Follow-up: compose resident ModUp and ModDown¶

Outcome¶

Added coefficient basis switching and CKKS ModUp/ModDown to the resident session. Polynomial intermediates remain on the device transport. The previously tested standalone converter is now composed with NTT operations, whole-tower views, Q/P packing and the final P-inverse correction. This is local preparation; the November 19 GPU results apply to the earlier source.

Reasoning¶

The missing raw archive blocks timing interpretation but not exact operation composition. ModUp must preserve the original Q evaluations and transform only the data needed to create P. ModDown must inverse-transform P, form and transform the Q correction, then subtract and scale. A chain cannot safely borrow stack-local conversion tables while GPU work is pending.

Changes¶

  • Added explicit-layout upload, coefficient switch_basis, mod_up and mod_down to the public resident prototype.
  • Added packed parameter tables, range copies, conversion and correction arithmetic to both the deferred CPU transport and CUDA adapter.
  • Charged per-operation parameter storage against device/host budgets and retained it with queued work before submission. A failed unproven drain keeps tables, staging and operands alive.
  • Added Stats::parameter_uploads separately from polynomial transfers. Upload → ModUp → ModDown → download has one polynomial upload, three small parameter uploads and one final polynomial download, excluding fixed session setup tables.
  • Extended the existing host/native OpenFHE fixture and resident controls. The collector already requires that native test and runs its expanded smoke case under all four sanitizer tools.
  • Updated the conversion guide, resident guide, backlog, roadmap and rental queue. P2/D11 stays open.

Verification¶

The full CPU/OpenFHE build passes all 29 CTests. The expanded resident comparison covers N=64/4096/65536, five active Q levels, mixed 30/50/55/60-bit primes, four patterns and an additional 40-Q/three-P dense case. It compares both ModUp input formats, independent ModDown, composition, input immutability and offset tower views with actual OpenFHE.

The latest host control suite passes 450 checks, including every injected transport failure and every failure after enqueue in the conversion chain. Parameter device/host budget rejections and retention during unproven drain also pass. The suite passes AddressSanitizer, UndefinedBehaviorSanitizer and leak detection.

Stock CUDA 13.0.88 builds the new adapter and native fixture for sm_89 and sm_120 in both default and legacy schedules. Three default-build driver-free preflight tests and the legacy resident preflight pass. No new GPU kernel, GPU sanitizer or performance run was executed in this workspace.

All 27 documentation tests and 14 Node math/interaction tests pass. The build validates 43 notebook pages with 16 journal entries. Chromium passes 248 page/width checks across all 62 website pages at 1440/1024/375/320 pixels, including 164 expanded article/journal checks. Math, contrast, English text, unique IDs, theme, navigation, search and existing interactive lessons pass without script/HTTP errors or page-wide overflow. Desktop and phone screenshots were inspected. Source CI and public deployment follow the two repository pushes.

Open questions¶

The new conversion chain requires its own native exactness and sanitizer run. Conversion-plan caching, allocator reuse, GPU Hybrid key switching and production integration remain future work. Real driver/context failures and primary RTX 5090 acceptance are still open. The raw November 19 measurement archive remains unavailable here.

Next step¶

Publish the source and revised guides, then run the expanded resident gate on the next RTX 5090 session. Analyze the existing Ada measurements when the verified archive is transferred from the M1 Pro.
