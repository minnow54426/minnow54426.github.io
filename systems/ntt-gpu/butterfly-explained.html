ntt-gpu · a beginner's field guide

NTT and butterflies.

An NTT turns one expensive polynomial multiplication into many small, repeated butterfly operations.

no prerequisites examples use mod 5 and mod 17 interactive diagrams
the only shape this whole page needs

The idea in four steps

Read this first. The chapters below explain why each step is valid.

1 · StartA polynomial is stored as a list of coefficients.
2 · TransformThe NTT evaluates that list at special modular points.
3 · ReuseA butterfly computes one shared sum-and-difference pair.
4 · RepeatN/2 butterflies across log₂N stages finish the transform.

Shortest path: data → NTT → sum to butterfly → butterfly → network → negacyclic. The other chapters are optional detail.

01

Start with coefficients

The input is a list of N numbers. In this page, that list represents a polynomial:

3slot 07slot 1 1slot 29slot 3 4slot 40slot 5 5slot 62slot 7

For this project, N is 65,536. We need to multiply two such lists efficiently:

multiply two lists of length N, get back a list of length N

The NTT (Number Theoretic Transform) is how that multiplication gets done fast. (How the product stays length N — the fold rule — is chapter 9's story.)

02

Choose special modular points

Modulo 17, start at 1 and keep multiplying by 2. After eight different values, the sequence returns to 1:

The wheel — the eight powers of 2, mod 17 · start at 1, keep multiplying by 2
dashed diameters: opposite points sum to 17 = q — each is the other's negative (property iii, halfway = minus)

Eight different numbers, then the ninth step lands back on 1. The powers of 2 form a closed loop of exactly 8 points — a wheel. Such a number is a root of unity ("unity" just means 1): \(ω^N = 1\), and primitive if no earlier power comes home. Everything the NTT relies on is a property of this wheel:

Nothing sacred about 2 — mod 17 offers four primitive 8th roots: 2, 8, 9, 15. Each walks the same eight points in a different order; 2 just gives the easiest multiplication table.

Optional: why these points make the NTT fast
i.

Closed: multiply = move

Powers never leave the wheel: \(ω^{a}\,ω^{b} = ω^{a+b}\) — multiplying just adds positions, a clock for multiplication (the logarithm trick). Why: one number generates all N plug-in points, one multiplication each.

ii.

Distinct: nothing is lost

A primitive root visits N different points, so N plugged-in values pin the list down exactly — the coordinates are reversible. Why: the transform has an inverse. The one demand on the prime: N | q−1 (ntt.hpp:61).

iii.

Halfway = minus

\(ω^{N/2} = -1\): opposite points are negatives (above: 1↔16, 2↔15, 4↔13, 8↔9 — each pair sums to 17). Why: the ± that makes output pairs — the butterfly's two wings (chapter 6).

iv.

Squaring = a half wheel

Every second point closes after N/2 steps: a half-size wheel with root ω². Why: wheels nest — the transform builds itself from half-size copies, the source of every "repeat" in chapter 5.

Why not just any N distinct numbers?

Any N distinct points make chapter 3's trick correct. Only wheel points make it fast: the shared brackets of chapter 5 are this wheel's symmetries showing up as algebra. The speed of the NTT is wheel symmetry.

03

What the NTT does

A list like \((2, 1)\) is a tiny machine: plug a number t in for x, get a value out. And plugged-in values multiply one by one:

\[(A\cdot B)(t) = A(t)\times B(t)\]

One multiplication, no crossing terms — and it holds for every t. Both roads below use \(t = 2\) (mod 5); change any coefficient and they still agree:

Road 1 costs four multiplies and still knows the product at only one point. Road 2 costs one multiply — and the equation below runs Road 2 at every wheel point at once.

To pin the product down we need its values at N different points — chapter 2's wheel supplies them.

the definition · the whole transform in one line
\[A_j = a_0+a_1\omega^j+a_2\omega^{2j}+a_3\omega^{3j}+\cdots \pmod{q}\]

Evaluating the list at all N wheel points is the NTT. Output j is the list plugged in at wheel point ωʲ — and because the points are distinct (wheel property ii), the transform inverts:

evaluate → multiply pointwise → invert  replaces a list multiplication with N plain multiplies. The rest of this page makes that round trip cheap.

Why "NTT" and not "FFT"?

The FFT does this with decimals — but decimals round, and rounding errors compound. The NTT does the same idea with whole numbers mod a prime: exact forever. Its wheels exist whenever N | q−1 — checked at ntt.hpp:61.

04

Direct evaluation vs butterflies: work saved

The equation demands N outputs, each a sum of N products — computed one by one, that's \(N \times N\) multiplications per transform:

Radix-2 uses \(N/2\) butterflies in each of \(\log_2 N\) stages. At N=65536, direct evaluation forms 4,294,967,296 products; the network uses 524,288 butterflies. The ratio is 8192:1 in these different counting units.

This compares arithmetic counts, not measured speed. A cyclic butterfly uses one multiply, one add and one subtract; this repository's folded negacyclic device butterfly uses two multiplies. CPU twiddle advancement adds another multiply. Doubling N multiplies the direct count by 4, and the butterfly count by \(2(\log_2N+1)/\log_2N\). The butterfly curve is slightly curved on a log–log plot.

05

Turn the NTT sum into butterflies

Start from the ordinary NTT definition. For output index k, direct evaluation forms one N-term sum:

\[ A_k = \sum_{r=0}^{N-1} a_r\,\omega^{rk}, \qquad 0\leq k<N \]

Split the exact sum into even and odd input indices. Write \(r = 2m\) for even indices and \(r = 2m+1\) for odd indices:

\[ \begin{aligned} \textcolor{#14655A}{E_k} &= \sum_{m=0}^{N/2-1} a_{2m}\,(\omega^2)^{mk} \\ \textcolor{#C2410C}{O_k} &= \sum_{m=0}^{N/2-1} a_{2m+1}\,(\omega^2)^{mk} \\[0.5em] A_k &= \textcolor{#14655A}{E_k} + \omega^k\,\textcolor{#C2410C}{O_k} \end{aligned} \]

Now look at the output halfway around the wheel. Since \(ω^{N/2} = -1\), its odd half changes sign while its even half does not:

\[ \begin{aligned} A_{k+N/2} &= \textcolor{#14655A}{E_k} - \omega^k\,\textcolor{#C2410C}{O_k} \\ t &= \omega^k O_k \\[0.5em] (A_k,\ A_{k+N/2}) &= (E_k+t,\ E_k-t) \end{aligned} \]

That final pair is one butterfly. The two outputs reuse the same \(E[k]\), the same \(O[k]\), and—most importantly—the same multiplication \(t = ω^k\,O[k]\).

1 · DIRECT

Compute N independent sums, each with N terms.

\(\text{cost: } O(N^2)\)
2 · SPLIT

Separate every sum into its even-index and odd-index terms.

\(A=E+\omega^k O\)
3 · SHARE

Pair outputs k and k+N/2. They share everything except a sign.

\(E+t,\ E-t\)
4 · RECURSE

E and O are smaller NTTs using the root ω². Split them again.

\(\log_2 N\text{ stages}\)

Why the optimization keeps working

\(ω^{2}\) is an N/2-th root of unity, so E and O have exactly the same shape as the original problem, only half as large. Repeating the split reaches two-value problems. Each level contains N/2 butterflies, and there are log₂N levels.

What exactly happens in each stage?

For this cyclic DIT explanation, first place input coefficients in bit-reversed order. Stage s starts at zero, uses group width M and distance d, and combines two completed half-transforms. Every pair reads the previous stage and writes two new values:

\[ M=2^{s+1},\quad d=M/2,\quad U=gM+j,\quad V=U+d,\quad 0\le j<d, \qquad t=\omega_N^{jN/M}X^{(s)}_V. \] \[ X^{(s+1)}_U=X^{(s)}_U+t,\qquad X^{(s+1)}_V=X^{(s)}_U-t. \]

Stage 0 combines pairs into 2-point transforms; stage 1 combines two 2-point results into a 4-point result; stage s combines two d-point results into one M-point result. A stage has N/M groups and d butterflies per group, giving N/2 disjoint pairs. A later stage must wait until its input stage finishes. The complete numerical example in the negacyclic section uses the repository's opposite, DIF stage order.

The handwritten derivation below expands N=4, recurses into the second split, and derives the twiddle exponent for every stage. Try its four-point arithmetic here first:

05+

Recursive decomposition and twiddle factors

This derivation follows the handwritten notes from the even/odd split through a second recursion, a four-point network, and the twiddle exponent at every stage. It then connects those results to this repository's negacyclic DIF implementation.

Notation

In the ordinary NTT portion of the notes, φ denotes a primitive N-th root of unity; here we write ωN, with ωNN/2 = −1. This repository uses ψ, a primitive 2N-th root of unity, with ψN = −1 and ωN = ψ². The ordinary NTT requires N to divide q−1 and works modulo xN−1; the negacyclic form requires 2N to divide q−1 and works modulo xN+1. All arithmetic below is modulo a prime q, and N is a power of two.

1. Split one N-point NTT into two half-length NTTs

Start with the definition: i indexes the input coefficients and j indexes the outputs. Split i into 2r and 2r+1:

\[ \begin{aligned} b_j&=\sum_{i=0}^{N-1}a_i\omega_N^{ij}\\ &=\sum_{r=0}^{N/2-1}a_{2r}\omega_N^{2rj} +\sum_{r=0}^{N/2-1}a_{2r+1}\omega_N^{(2r+1)j}\\ &=\underbrace{\sum_{r=0}^{N/2-1}a_{2r}(\omega_N^2)^{rj}}_{A_j} +\omega_N^j\underbrace{\sum_{r=0}^{N/2-1}a_{2r+1}(\omega_N^2)^{rj}}_{B_j}. \end{aligned} \]

A is the N/2-point NTT of the even-index coefficients; B is the N/2-point NTT of the odd-index coefficients. Both use the root ωN² = ωN/2. Both are periodic in j with period N/2, so only 0 ≤ j < N/2。

\[ \begin{aligned} A_{j+N/2}&=A_j,\qquad B_{j+N/2}=B_j,\\ \omega_N^{j+N/2}&=-\omega_N^j,\\ b_j&=A_j+\omega_N^jB_j,\\ b_{j+N/2}&=A_j-\omega_N^jB_j. \end{aligned} \]

This produces one butterfly pair: compute t = ωNjBj once, then output Aj+t and Aj−t. The output indices differ by N/2 and share one multiplication.

2. Recurse: where do ω² and ω⁴ come from?

Split A's input sequence again. Its even and odd positions correspond to a4r and a4r+2 in the original array:

\[ \begin{aligned} A_j&=\sum_{r=0}^{N/4-1}a_{4r}\omega_N^{4rj} +\omega_N^{2j}\sum_{r=0}^{N/4-1}a_{4r+2}\omega_N^{4rj}\\ &=C_j+\omega_N^{2j}D_j,\\ C_j&=\sum_{r=0}^{N/4-1}a_{4r}(\omega_N^4)^{rj},\qquad D_j=\sum_{r=0}^{N/4-1}a_{4r+2}(\omega_N^4)^{rj},\\ A_{j+N/4}&=C_j-\omega_N^{2j}D_j,\qquad 0\le j<N/4. \end{aligned} \]

The minus sign follows from (ωN²)N/4 = −1. Likewise, B splits into a4r+1 and a4r+3. Each recursion halves the length and squares the root: ωN → ωN² → ωN⁴ → …, down to length 2. Bottom-up combination visits these lengths in the opposite order.

3. N=4: expand the sums and draw the network

Let ω = ω4, so ω²=−1 and ω³=−ω. Expand all four outputs and regroup the shared intermediate values:

\[ \begin{aligned} b_0&=a_0+a_1+a_2+a_3=(a_0+a_2)+(a_1+a_3),\\ b_1&=a_0+a_1\omega+a_2\omega^2+a_3\omega^3=(a_0-a_2)+\omega(a_1-a_3),\\ b_2&=a_0+a_1\omega^2+a_2\omega^4+a_3\omega^6=(a_0+a_2)-(a_1+a_3),\\ b_3&=a_0+a_1\omega^3+a_2\omega^6+a_3\omega^9=(a_0-a_2)-\omega(a_1-a_3). \end{aligned} \]

The first level computes P=a₀+a₂, Q=a₀−a₂, R=a₁+a₃ and S=a₁−a₃. The second combines P and R into b₀ and b₂, and Q and S into b₁ and b₃. Only the latter pair needs a multiplication by ω.

The drawing's vertical order does not prescribe memory order. Standard iterative DIT usually starts with bit-reversed inputs and produces natural-order outputs. This repository's forward DIF takes natural-order inputs and produces bit-reversed evaluations. See the N=8 network and the D7 representation contract for the exact ordering.

4. Derive the stage twiddle from its length

Use the notes' bottom-up DIT combination, with s starting at zero. Stage s combines two 2s-point results into one M=2s+1-point result. Here j is the offset within the current butterfly group.

\[ \begin{aligned} M&=2^{s+1},\qquad 0\le s<\log_2N,\qquad 0\le j<M/2,\\ \omega_M&=\omega_N^{N/M},\\ w_{s,j}&=\omega_M^j=\left(\omega_N^{N/2^{s+1}}\right)^j =\boxed{\omega_N^{jN/2^{s+1}}}. \end{aligned} \]

A butterfly's factor follows from three quantities: stage s → group length M → local offset j. Groups in the same stage share the j-to-factor rule. The group number changes the array positions, not the exponent.

6. Connect the derivation to the forward negacyclic loop

The repository's forward transform is DIF. Stage t starts at zero, and distance d=N/2t+1 decreases. For group length M=2d and local offset J:

\[ \begin{aligned} E&=\frac{N}{2d}J,\qquad w=\omega_N^E=\psi^{(N/d)J},\qquad c=\psi^d,\\ (u,v)&\longmapsto\bigl(u+cv,\;(u-cv)w\bigr)\pmod q. \end{aligned} \]

The change-of-root rule still raises the global root to N/M, but stages run in the opposite direction and include c to fold the negacyclic twist. At N=65536 the first forward stage has d=32768 and w=ωNJ=ψ2J. In the final stage d=1, J must be 0 and w=1. DIT stage 0 is not the first stage of the repository's forward DIF.

The inverse uses reciprocal w and c, reverses the stage order, and finally multiplies by N⁻¹. For the exact coefficient indices, bit-reversed output order, and CUDA groups, see the forward and inverse work distribution。

06

Meet the butterfly

A butterfly takes two inputs and produces a sum and a weighted difference. The crossing wires give the circuit its name. These two common forms place the multiplier on different legs:

DIT — ① multiply the input, ② add / subtract · what chapters 5–7 derive
DIF — ① add / subtract, ② multiply the difference output · the same unit, run the other way
Same two wings — only the order of multiply vs ± differs (the gold ①②). DIT multiplies before the crossing, DIF after it. (The repo's negacyclic forward adds one refinement on top of DIF — a ladder constant ψ^d on the input leg; that is chapter 10's loop.)

Why are the inputs scrambled?

The leftmost values are in bit-reversed order (0,4,2,6,1,5,3,7 — index in binary, read backwards). That one upfront shuffle lets every stage read its partners from nearby positions and the outputs arrive in natural order. The repo ships the mirror image: a DIF forward (natural inputs, bit-reversed outputs) paired with a DIT inverse that consumes exactly that order — so in the real pipeline the two permutations cancel and no bit-reversal pass exists at all (bitrev.hpp documents the permutation itself).

And the negacyclic variant?

This network is the plain ("cyclic") transform. The negacyclic variant below uses the same pair network with a folded ψ factor on the lower input of each butterfly (ntt.hpp:87).

09

CKKS uses the negacyclic form

One loose end from chapter 1: the operation there was "multiply two lists, get back a list of the same length N." But plain multiplication lengthens the list:

\[(2+x)(3+2x)=6+7x+2x^2\]

If every multiplication grew the list, nothing could chain. The fix is one fold rule, in exactly two flavors:

\[ \begin{aligned} x^N &= +1 && \text{cyclic: wrap with a plus} \\ x^N &= -1 && \text{negacyclic: wrap with a minus} \end{aligned} \]

The cyclic fold is precisely the world of chapters 3–7: every ω-wheel point satisfies x^N = ω^N = 1. The negacyclic fold is the one this repo implements. With \(x^{2} = -1\) (N = 2, mod 5), the overflow folds back like this:

\[ 6+7x+2x^2 \;\longmapsto\; (6-2)+7x \;\equiv\; 4+2x \pmod{5} \]

All numbers live mod some prime (here mod 5) — only the remainder after dividing survives, so numbers stay tiny forever.

Which points respect the minus fold? Those with \(x^N = -1\) — the roots of \(x^N + 1\). They are the odd steps of a doubled wheel: a number ψ with \(ψ^N = -1\) closes after 2N points, and \((ψ^{\mathrm{odd}})^N = (-1)^{\mathrm{odd}} = -1\). Mod 17, ψ = 6, and \(ψ^{2} = ω\) — its even steps are chapter 2's wheel:

The key substitution: pre-twist, then use the ordinary NTT

Let \(ω = ψ^{2}\) and pre-twist coefficient r as \(b[r] = a[r]\,ψ^r\). An ordinary cyclic NTT of b then gives \(\sum_{r=0}^{N-1} b_r\omega^{rk} = \sum_{r=0}^{N-1} a_r\psi^{(2k+1)r}\). In other words, the twist moves evaluation from the even powers of ψ to exactly the odd powers—the roots of x^N+1. The inverse runs the cyclic inverse and multiplies coefficient r by \(ψ^{-r}\).

Derive the factors from the first split

Choose a primitive 2N-th root ψ in the current prime field, so ψᴺ=−1, and set ω=ψ². For power-of-two N, checking ψᴺ=−1 proves that ψ has order 2N. The prime must satisfy \(2N\mid(q-1)\). OpenFHE compatibility additionally requires the exact same ψ as its tower parameters; another primitive root changes the output order.

\[ F_k=\sum_{i=0}^{N-1}a_i\psi^{(2k+1)i} =\sum_{i=0}^{N-1}(a_i\psi^i)\omega^{ki}. \]

Now split input into a low half and a high half, d=N/2. This is the DIF split; the even/odd split above was DIT. The high-half factor contains a sign that depends only on k:

\[ \begin{aligned} F_k&=\sum_{j=0}^{d-1}\left[a_j+a_{j+d}\psi^{(2k+1)d}\right]\psi^{(2k+1)j},\\ \psi^{(2k+1)d}&=\psi^d(\psi^N)^k=(-1)^k\psi^d. \end{aligned} \]

Separate the even output indices k=2ℓ and odd indices k=2ℓ+1. Both smaller transforms use root ψ², but the odd branch needs an extra ψ²ʲ:

\[ \begin{aligned} F_{2\ell}&=\sum_{j=0}^{d-1}\underbrace{(a_j+\psi^d a_{j+d})}_{x_j}(\psi^2)^{(2\ell+1)j},\\ F_{2\ell+1}&=\sum_{j=0}^{d-1}\underbrace{(a_j-\psi^d a_{j+d})\psi^{2j}}_{y_j}(\psi^2)^{(2\ell+1)j}. \end{aligned} \]

The first split gives c=ψᴺᐟ² and w=ψ²ʲ. To derive all later folded factors without guessing a root for each branch, compare with the ordinary cyclic DIF network applied to the pre-twisted coefficients. At a current block of length 2d, let its cyclic values and folded values be related by \(b_j=\psi^j a_j\), where j is local to that block. The cyclic butterfly reads \(b_{j+d}=\psi^{j+d}a_{j+d}\):

\[ \begin{aligned} b'_j&=b_j+b_{j+d}=\psi^j(a_j+\psi^d a_{j+d}),\\ b'_{j+d}&=(b_j-b_{j+d})\omega_N^{jN/(2d)} =\psi^j(a_j-\psi^d a_{j+d})\omega_N^{jN/(2d)}. \end{aligned} \]

Both child blocks now have length d and local index j. Removing their common local twist ψʲ leaves the folded outputs \(x_j=a_j+\psi^d a_{j+d}\) and \(y_j=(a_j-\psi^d a_{j+d})\omega_N^{jN/(2d)}\). The same relation holds for the next split with d halved. Initially it is exactly the pre-twist; at length one j=0, so the remaining twist is 1. This proves every stage and the final result with no extra twist pass.

What stays the same

The radix-2 network, paired indices, number of stages, and N/2 butterflies per stage do not change.

\[ \begin{aligned} u' &= u+v \\ v' &= (u-v)\,w \end{aligned} \]

What negacyclic changes

The ψ twist changes the factors carried by the butterfly. This repo folds it into the same pass instead of storing a separate twist table.

\[ \begin{aligned} u' &= u+cv \\ v' &= (u-cv)\,w \end{aligned} \]

For the repo's forward DIF loop, a stage pairs entries distance \(d\) apart. Its folded factors are:

\[ \begin{aligned} c_d &= \psi^d \\ w_{d,j} &= \psi^{\frac{N}{d}j} = \omega^{\frac{N}{2d}j} \\[0.5em] \mathrm{upper}' &= \mathrm{upper}+c_d\,\mathrm{lower} \\ \mathrm{lower}' &= (\mathrm{upper}-c_d\,\mathrm{lower})\,w_{d,j} \end{aligned} \]

The group number does not select the twiddle. At a fixed stage, every group repeats the same sequence: j starts at 0, so \(w = 1\), then advances by \(ψ^{N/d}\) for each butterfly offset. Negacyclic therefore changes the factors, not the network's pairing pattern. The inverse uses reciprocal ψ factors, reverses the stage direction, and applies the final \(N^{-1}\) scale.

10

Map the picture to code

Here is the actual loop from this repo's CPU reference (include/ntt/ntt.hpp, the forward DIF sweep — twist folded in as ladder constants, natural values in, bit-reversed values out). Read the comments with chapter 7 open next to it — every line is a part of the picture:

for (uint64_t stage_pair_distance = n_ / 2;
     stage_pair_distance >= 1; stage_pair_distance >>= 1) {
  const uint64_t ladder_twiddle =
      pow_mod(psi_, stage_pair_distance, q_);             // c_d = ψ^d
  const uint64_t twiddle_step =
      pow_mod(psi_, n_ / stage_pair_distance, q_);        // ψ^(N/d)
  for (uint64_t group_start_index = 0; group_start_index < n_;
       group_start_index += 2 * stage_pair_distance) {
    uint64_t twiddle_power = 1;                         // j = 0
    for (uint64_t pair_offset = 0;
         pair_offset < stage_pair_distance; ++pair_offset) {
      const uint64_t upper_index = group_start_index + pair_offset;
      const uint64_t lower_index = upper_index + stage_pair_distance;
      const uint64_t upper_value = values[upper_index];
      const uint64_t scaled_lower_value =
          mul_mod(ladder_twiddle, values[lower_index], q_);
      values[upper_index] =
          add_mod(upper_value, scaled_lower_value, q_);      // upper + c_d·lower
      values[lower_index] = mul_mod(
          sub_mod(upper_value, scaled_lower_value, q_),
          twiddle_power, q_);                                  // (upper − c_d·lower)·w_d,j
      twiddle_power = mul_mod(twiddle_power, twiddle_step, q_);
    }
  }
}

Three nested loops, one idea: for every butterfly in every stage — u+v, u−v. The CUDA port assigns independent pairs to threads and fuses several stages inside a shared-memory block. At N=65536, one forward transform uses two launches; it does not launch a separate kernel for every stage.

Recap

The NTT evaluates a polynomial at modular roots of unity. Reusing even/odd subtransforms reduces N² direct products to (N/2)·log₂N butterflies. At N=65,536 that is 524,288 butterflies. CKKS uses odd powers of a primitive 2N-th root, giving multiplication modulo x^N+1.
